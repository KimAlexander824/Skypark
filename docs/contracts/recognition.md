# Контракт сервиса распознавания (версия 1)

Как другие сервисы (backend) пользуются распознаванием лиц. Пока контракт не меняется,
каждый сервис можно переписывать как угодно внутри.

**Правило изменений:** добавлять новые поля и задачи можно свободно. Менять или удалять
существующие — только договорившись и подняв версию контракта.

## Как вызывать

Через очередь BullMQ в Redis.

| | |
|---|---|
| Redis | `REDIS_URL` (в docker-compose: `redis://redis:6379`) |
| Очередь | `recognition` |
| Готовый клиент на Python | `services/recognition/client/recognition_client.py` — скопировать к себе, `pip install bullmq` |

```python
from recognition_client import RecognitionClient

rc = RecognitionClient("redis://redis:6379")

# 1) положить и дождаться (фронтенд делает один запрос)
result = await rc.identify(photo_bytes)

# 2) как на схеме: POST кладёт задачу, GET спрашивает результат
job_id = await rc.submit_identify(photo_bytes)   # вернуть фронтенду {"job_id": job_id}
info = await rc.get_result(job_id)               # {"state": "completed", "result": {...}}
```

Клиент сам ставит повторы при сбоях (3 попытки, экспоненциальная пауза от 1 с) и приоритеты:
поиск — самый срочный, регистрация — следом, фоновые задачи — последними.

## Задачи

Фото передаётся в поле `photo` как base64 (JPEG или PNG, до 10 МБ).

### `identify` — найти ребёнка по фото

Данные: `{"photo": "<base64>"}`

Результат:
```json
{
  "ok": true,
  "status": "found",
  "child_id": 7,
  "confidence": 0.93,
  "message": "Ребёнок найден",
  "candidates": [{"child_id": 7, "confidence": 0.93, "is_match": true}]
}
```

| `status` | Что значит | Что делать |
|---|---|---|
| `found` | ребёнок найден | открыть карточку `child_id` |
| `not_found` | похожих нет | регистрация или поиск по телефону |
| `ambiguous` | 2+ детей почти одинаково похожи | сотрудник выбирает из `candidates` |

`candidates` — до 3 самых похожих детей. `confidence` — сходство от 0 до 1.

### `enroll` — запомнить лицо ребёнка

Данные: `{"child_id": 7, "photo": "<base64>", "source": "registration"}`

- `source = "registration"` — фото при регистрации, в кадре должно быть ровно одно лицо;
- `source = "visit"` — фото с повторного визита, берётся самое крупное лицо. Добавлять его стоит
  только при уверенном совпадении (`found` и `confidence` ≥ 0.6).

Результат:
```json
{"ok": true, "face_id": 15, "child_id": 7, "shard": 1, "det_score": 0.87, "source": "registration", "faces_count": 1}
```

На ребёнка хранится до 5 фото: фото с регистрации — всегда, остальные места занимают самые свежие.

### `delete_faces` — удалить биометрию ребёнка

Данные: `{"child_id": 7}`. Backend кладёт эту задачу, когда удаляет ребёнка или родитель
просит удалить фото (§42). Повторный вызов безопасен.

Результат: `{"ok": true, "child_id": 7, "deleted": 3}`

## Ошибки

**Плохое фото — это обычный ответ, а не сбой.** Задача завершается (`completed`) с результатом:

```json
{"ok": false, "error": "no_face", "message": "Лицо не найдено. Сфотографируйте ребёнка анфас при хорошем свете"}
```

| `error` | Когда | Что показать сотруднику |
|---|---|---|
| `bad_image` | файл не читается как картинка | выбрать другой файл |
| `no_face` | лицо не найдено | переснять анфас при хорошем свете |
| `low_quality` | лицо меньше 80 px | подойти ближе |
| `multiple_faces` | при регистрации в кадре несколько лиц | переснять одного ребёнка |

`message` можно показывать сотруднику как есть.

**Сбой** (база или нейросеть недоступны) — задача повторяется автоматически. Если все попытки
не удались, задача получает статус `failed`. Клиент в этом случае бросает `RecognitionJobFailed`:
сотрудник ищет ребёнка по телефону (§43).

**Неверная задача** (нет поля, `child_id` не число, неизвестное имя) — сразу `failed`, без повторов.

## Регистрация ребёнка без общей транзакции

У сервисов разные базы, поэтому «сохранить ребёнка и лицо одной транзакцией» нельзя.
Порядок действий:

1. `identify` — проверить, нет ли ребёнка уже в базе (`found` → показать «похоже, уже зарегистрирован»).
2. Создать ребёнка у себя, получить `child_id`.
3. `enroll` с `source="registration"`.
4. Если `ok: false` (плохое фото) или `RecognitionJobFailed` — удалить ребёнка у себя
   (или пометить «без фото») и попросить переснять.

## Удаление ребёнка

Внешнего ключа между сервисами нет. Удаляя ребёнка, backend кладёт задачу `delete_faces`.

## Хранение задач

Выполненные задачи (с фото и результатом) удаляются из Redis через 10 минут, упавшие — через час.
За это время backend должен забрать результат.
