# Техническое задание
# Система автоматизации «СКАЙПАРК»

**Версия:** 1.0  
**Статус:** Draft (черновик)  
**Тип продукта:** Web-система + Telegram-бот + административная панель  
**Цель:** автоматизация регистрации детей, учёта посещений, работы нянь, продлений и взаимодействия с родителями.

---

# 1. Общая информация

## 1.1. Назначение системы

Система «СКАЙПАРК» предназначена для автоматизации процесса посещения детского развлекательного пространства.

Система должна заменить ручной учёт детей и посещений и предоставить единое пространство для:

- регистрации детей;
- хранения карточек детей и родителей;
- повторной идентификации ребёнка;
- назначения няни;
- учёта времени посещения;
- контроля текущих посещений;
- продления времени;
- онлайн-оплаты;
- уведомления родителей;
- управления сотрудниками и нянями;
- получения статистики и аналитики.

---

# 2. Цели проекта

Основная цель — сократить время оформления повторного посещения и автоматизировать весь цикл пребывания ребёнка.

### Целевой процесс

**Регистрация → идентификация → назначение няни → выбор времени → посещение → уведомление → продление/завершение → оплата → завершение посещения.**

---

# 3. Пользователи системы

В системе предусматриваются следующие роли:

| Роль | Основные функции |
|---|---|
| Сотрудник Скайпарка | Регистрация и оформление посещений |
| Няня | Контроль назначенных детей |
| Родитель | Получение уведомлений и продление через Telegram |
| Администратор | Управление системой и просмотр аналитики |

# 5. Модуль детей

## 5.1. Регистрация ребёнка

Сотрудник должен иметь возможность создать карточку ребёнка.

### Шаг 1. Родитель

Сотрудник вводит:

- номер телефона;
- имя родителя;
- при необходимости дополнительные данные.

Система должна проверять, существует ли родитель с указанным номером.

Если родитель существует, система предлагает выбрать одного из уже зарегистрированных детей.

Если родителя нет — создаётся новая запись.

---

## 5.2. Данные ребёнка

При создании карточки необходимо указать:

- имя;
- фамилию;
- дату рождения;
- пол;
- фотографию;
- дополнительные данные при необходимости.

Перечень обязательных полей должен быть согласован до начала разработки.

---

# 6. Фотография и распознавание лица

## 6.1. Первичная регистрация

При первом посещении сотрудник фотографирует ребёнка.

Фотография сохраняется в карточке ребёнка.

Также система должна сохранять данные, необходимые для последующей идентификации ребёнка по лицу.

---

## 6.2. Повторное посещение

При повторном посещении сотрудник фотографирует ребёнка.

Система передаёт изображение в модуль распознавания.

Модуль должен:

1. обработать фотографию;
2. определить лицо;
3. найти совпадение среди зарегистрированных детей;
4. вернуть найденного ребёнка;
5. открыть его карточку.

Если совпадение не найдено:

> «Ребёнок не найден. Зарегистрировать нового ребёнка или выполнить поиск по номеру телефона».

---

## 6.3. Ручной поиск

Помимо распознавания лица сотрудник должен иметь возможность найти ребёнка вручную.

Основной способ:

**номер телефона родителя.**

После ввода номера система отображает всех детей, связанных с данным родителем.

---

# 7. Карточка ребёнка

Карточка ребёнка должна содержать:

### Основная информация

- фотографию;
- имя;
- фамилию;
- дату рождения;
- пол.

### Информация о родителе

- имя;
- номер телефона;
- Telegram;
- список детей.

### Посещения

- дата;
- время начала;
- время окончания;
- назначенная няня;
- продолжительность;
- факт продления;
- стоимость;
- статус оплаты;
- статус посещения.

### История

Система должна сохранять историю всех посещений ребёнка.

---

# 8. Родитель и несколько детей

Один родитель может иметь несколько детей.

Например:

**Родитель: Иван Иванов**

- Анна Иванова;
- Максим Иванов;
- София Иванова.

Все дети должны быть связаны с одним родителем.

При регистрации нового ребёнка сотрудник должен иметь возможность выбрать существующего родителя.

---

# 9. Модуль посещений

Посещение является отдельной сущностью системы.

## 9.1. Создание посещения

После идентификации ребёнка сотрудник:

1. выбирает ребёнка;
2. выбирает свободную няню;
3. выбирает продолжительность;
4. система рассчитывает стоимость;
5. создаётся посещение;
6. запускается таймер;
7. ребёнок появляется у назначенной няни.

---

# 10. Выбор няни

Сотруднику отображается список доступных нянь.

Для каждой няни необходимо показывать:

- имя;
- фотографию;
- статус;
- текущую загрузку;
- количество детей;
- доступность.

### Возможные статусы

- Свободна;
- Занята;
- Перерыв;
- Не работает.

Нельзя назначить ребёнка няне, которая недоступна.

---

# 11. Учёт времени

После начала посещения система запускает таймер.

Например:

**Начало:** 14:00  
**Продолжительность:** 2 часа  
**Окончание:** 16:00

Система должна автоматически рассчитывать:

- прошедшее время;
- оставшееся время;
- время окончания.

---

# 12. Завершение посещения

Посещение может завершиться двумя способами:

### Автоматически

Когда заканчивается оплаченный период.

### Вручную

Сотрудник завершает посещение раньше установленного времени.

При завершении:

- статус посещения изменяется на «Завершено»;
- няня освобождается;
- посещение сохраняется в истории;
- родителю отправляется уведомление.

---

# 13. Интерфейс няни

Няня должна видеть список детей, которые в данный момент находятся у неё.

Для каждого ребёнка отображается:

- фотография;
- имя;
- время начала;
- время окончания;
- оставшееся время;
- информация о продлении.

Пример:

| Ребёнок | Начало | Окончание | Осталось |
|---|---:|---:|---:|
| Анна | 14:00 | 16:00 | 35 мин |
| Максим | 15:00 | 17:00 | 1 ч 35 мин |

---

# 14. Telegram-бот для родителей

Родитель взаимодействует с системой через Telegram.

При первой привязке номер телефона родителя должен быть связан с Telegram-аккаунтом.

---

# 15. Уведомления

Система должна отправлять родителю уведомления о событиях посещения.

### Основные уведомления

1. Посещение началось.
2. До окончания осталось 15 минут.
3. Посещение продлено.
4. Продление не требуется.
5. Посещение завершено.
6. Оплата успешно проведена.
7. Ошибка оплаты.

---

# 16. Продление посещения

За **15 минут до окончания** система автоматически отправляет уведомление.

Пример:

> Ваше время посещения ребёнка заканчивается через 15 минут. Хотите продлить посещение?

Кнопки:

- **Продлить**
- **Не продлевать**

---

# 17. Продление

При выборе «Продлить»:

### Шаг 1

Родитель выбирает дополнительное время.

Например:

- +30 минут;
- +1 час;
- +2 часа.

Набор вариантов должен быть настраиваемым администрацией.

### Шаг 2

Система рассчитывает стоимость.

Например:

**Дополнительно: 1 час**  
**Стоимость: 50 000 сум**

### Шаг 3

Родитель выполняет онлайн-оплату.

### Шаг 4

После успешной оплаты:

- посещение продлевается;
- время окончания изменяется;
- информация обновляется у няни;
- родитель получает подтверждение.

---

# 18. Отказ от продления

Если родитель выбирает:

**«Не продлевать»**

система:

1. фиксирует решение;
2. отправляет информацию сотруднику;
3. оставляет исходное время окончания;
4. после окончания времени завершает посещение.

---

# 19. Онлайн-оплата

Для продления должна быть предусмотрена онлайн-оплата.

Статусы платежа:

- Создан;
- Ожидает оплаты;
- Оплачен;
- Ошибка;
- Отменён;
- Возвращён.

Конкретный платёжный провайдер определяется отдельно.

# 39. Требования к распознаванию лица

Модуль распознавания лица должен:

- принимать фотографию ребёнка;
- определять наличие лица;
- сравнивать лицо с зарегистрированными профилями;
- возвращать идентификатор найденного ребёнка;
- возвращать уровень уверенности совпадения;
- корректно обрабатывать отсутствие совпадения.

Необходимо предусмотреть сценарий:

**«Распознавание не удалось → ручной поиск по номеру телефона».**

Конкретная технология распознавания определяется на этапе технического проектирования.

# 41. История изменений

Система должна сохранять историю ключевых действий.

Например:

- кто зарегистрировал ребёнка;
- кто создал посещение;
- кто назначил няню;
- кто завершил посещение;
- кто изменил время;
- кто применил скидку;
- кто создал промокод.

Это необходимо для последующего контроля действий сотрудников.

# 42. Требования к безопасности

Необходимо обеспечить:

- авторизацию пользователей;
- разграничение доступа по ролям;
- защищённое хранение персональных данных;
- защищённую передачу данных;
- защиту административной панели;
- журналирование критических действий;
- ограничение доступа к фотографиям детей.

Особое внимание необходимо уделить обработке биометрических данных, поскольку система использует распознавание лица.

Правовые требования к хранению и обработке таких данных необходимо отдельно согласовать для юрисдикции, в которой будет использоваться Система.

---

# 43. Нефункциональные требования

Система должна обеспечивать:

### Производительность

Основные операции интерфейса должны выполняться без заметных задержек.

### Надёжность

При временной недоступности Telegram, платёжной системы или сервиса распознавания основная информация о посещении не должна теряться.

### Масштабируемость

Архитектура должна позволять в дальнейшем добавлять:

- несколько филиалов;
- дополнительные тарифы;
- дополнительные способы оплаты;
- дополнительные каналы уведомлений;
- расширенную аналитику.

---

# 44. Обработка ошибок

Необходимо предусмотреть ошибки:

### Распознавание

- лицо не найдено;
- несколько лиц;
- низкое качество фотографии;
- ребёнок не найден.

### Оплата

- платёж отклонён;
- платёж отменён;
- платёж не подтверждён;
- платёжный сервис недоступен.

### Telegram

- пользователь не привязан;
- сообщение не доставлено;
- бот недоступен.

### Посещение

- няня недоступна;
- Скайпарк закрыт;
- выбранное время недоступно;
- ребёнок уже находится на посещении.

# 47. Критерии готовности MVP

MVP считается готовым, если пользователь может пройти полный сценарий:

### Первое посещение

**Создать родителя → создать ребёнка → сфотографировать → создать карточку → выбрать няню → выбрать время → начать посещение.**

### Повторное посещение

**Сфотографировать ребёнка → распознать → найти карточку → выбрать няню → выбрать время → начать посещение.**

### Продление

**Отправить уведомление за 15 минут → выбрать продление → выбрать время → оплатить → увеличить время посещения.**

### Завершение

**Закончить посещение → освободить няню → сохранить историю → отправить уведомление родителю.**

### Администрирование

Администратор должен иметь возможность:

**управлять детьми → управлять нянями → управлять сотрудниками → просматривать посещения → просматривать оплаты → просматривать Dashboard → управлять скидками и промокодами.**
